# Экспертная валидация — как выложить, как выдать доступ, что нужно от бэкенда

Экран эксперта — `expert.html`, сводка — `expert-report.html`. Обе страницы
статические и лежат там же, где остальная платформа: **отдельная ссылка
получается сама**, потому что это отдельный файл.

```
https://<адрес платформы>/expert.html          ← эксперту
https://<адрес платформы>/expert-report.html   ← команде
```

С витрины и из ассессмента на них никто не ссылается, в `<head>` стоит
`noindex, nofollow`. Ничего дополнительно настраивать не нужно: выкладываете
как обычно.

---

## 1. Два разных пароля. Их легко перепутать, а они делают разное

**Пароль эксперта** (например `082026`) — то, что вы присылаете вместе со
ссылкой. Это не пропуск, а **ключ**: им зашифрован сам корпус описаний.

Разница принципиальная. Пароль-пропуск, который страница сверяет со строкой в
своём коде, не защищает ни от чего — исходник открывается в два клика, а файл
корпуса скачивается по прямому адресу мимо всякой проверки. Здесь пароля в коде
нет вообще: на сервере лежит шифротекст, и без пароля пятьдесят описаний — шум.

Зачем это нужно: `js/expert-corpus.js` — рубрика, по которой ставится уровень.
Участник ассессмента, прочитавший её до кейса, ломает замер, а ссылки живут
рядом.

**Пароль команды** — тот, которым открывается выгрузка ответов с сервера в
сводке. Он проверяется **на бэкенде**, экспертам не выдаётся и в коде не лежит.

---

## 2. Собрать корпус

```
node tools/build-expert-corpus.js ~/Desktop/FP/01_methodology_v11.md expert-levels.md 082026
```

Файлов два, и это разные роли. Из методологии берётся только карта модели
(§5.1–5.3) — справочник, который эксперт видит на экране. Пятьдесят карточек
берутся из `expert-levels.md`: §10 написан для судьи, у которого перед глазами
все пять уровней, кейс и граничные тесты, а эксперт видит одну карточку из
пятидесяти и не знает даже, к какой способности она относится. Всё, что в §10
держится на соседнем уровне, на кейсе или на перекрёстной ссылке, при нарезке
становилось либо подсказкой, либо обрывком. `expert-levels.md` — переложение
§10 под эту задачу; правила переложения записаны в шапке самого файла.

Третий аргумент — пароль эксперта. Скрипт кладёт `js/expert-corpus.js`
зашифрованным и сразу проверяет обратную расшифровку: записать нечитаемый файл
молча — худший исход, обнаружился бы он на эксперте.

Файл **коммитится и публикуется как обычный**: без пароля он ничего не значит.

**Смена пароля = пересборка.** Старый пароль после неё перестаёт открывать
страницу, а эксперты, которым вы его уже дали, упрутся в «пароль не подошёл».
Меняйте между волнами, не посреди.

Скрипт при каждой сборке печатает, что вычистил и что стоит вычитать глазами.
Четыре предупреждения означают работу в самой методологии, а не в коде:

- **уровни без блока «Суть»** — карточка собрана из одних признаков;
- **порядок читается по одной длине карточки** — там блок Б ничего не измерит,
  описания уровней надо выровнять по объёму;
- **карточка начинается со ссылки на то, чего в ней нет** — вычистка вырезала
  предложение, на которое опиралось следующее;
- **короткие карточки** — стоит перечитать.

## 3. Номер эксперта

При первом входе страница выдаёт **четырёхзначный номер** и показывает его
сразу, до работы, а не только на финише: закрыть вкладку можно на любой
карточке.

- **тот же компьютер** — достаточно открыть ту же ссылку, номер в адресе;
- **другой компьютер** — открыть `expert.html?e=7742` и ввести пароль.

Второе работает только с бэкендом: без него ответы лежат в браузере эксперта.

> ⚠ **Номер каждый браузер выдаёт себе сам** — они друг о друге не знают, и
> двое экспертов теоретически могут получить одинаковый; тогда второй пишет
> поверх первого. При 9000 номеров и двенадцати экспертах это примерно 0.7%
> прогонов (при трёхзначных было бы 7% — потому и четыре цифры). До нуля это
> не доводит, поэтому при возврате по номеру страница показывает имя владельца
> и спрашивает «это вы?».

## 4. Отдельный скрипт Apps Script

**Не тот, что обслуживает ассессмент.** Там уже лежат прогоны, ответы,
судейство и правки; здесь другие данные, другой объём и другой срок жизни —
разбор нужен на несколько недель, потом лист можно закрыть. Общий скрипт связал
бы их отказы: сломался бы один лист — встали бы оба экрана.

**Готовый код — в `backend/expert.gs`.** Его не нужно писать, нужно вставить.

1. Новая Google-таблица → **Расширения → Apps Script**.
2. Заменить содержимое `Code.gs` файлом `backend/expert.gs` целиком.
3. Поменять `TEAM_PASSWORD` в первых строках. Это пароль **команды**, не тот,
   что выдаётся экспертам: совпадать они не должны.
4. **Развернуть → Новое развёртывание → Веб-приложение.**
   «Запуск от имени» — *Я*. «У кого есть доступ» — *Все*.
   Второе обязательно: браузер эксперта приходит без входа в Google.
5. Скопировать URL (`…/exec`) → `js/expert-api.js`, переменная `EXPERT_API_URL`.

Проверка, что живо: открыть этот же URL в браузере — скрипт ответит
`{"ok":true,…}` и покажет, сколько экспертов записано и сменён ли пароль.
Лист `experts` создастся сам при первом сохранении.

> ⚠ После каждой правки скрипта — **Развернуть → Управление развёртываниями →
> карандаш → Версия: новая**. Без этого по старому URL продолжает работать
> старый код. Это самая частая потеря времени здесь.

Пока `EXPERT_API_URL` пуст, обе страницы работают на `localStorage`, а на финише
эксперту предлагается выгрузка файлом — сводка эти файлы принимает.

Ниже — что скрипт принимает и отдаёт, если понадобится его менять.

### `saveExpert`

```
{ action: 'saveExpert', key: '7742', expert: { … весь снимок … } }
```

Ответ `{ ok: true }`. Любой другой ответ клиент считает сбоем и кладёт снимок в
очередь повторной отправки — она есть в `js/expert-api.js` и работает сама.

Запись — **upsert по `key`**, одна строка на эксперта. Не append: снимок
приходит целиком и каждый раз новый.

Лист `experts`:

| колонка | что |
|---|---|
| `key` | номер эксперта, он же ключ upsert |
| `corpus` | версия корпуса (`meth-v11`) |
| `name` | имя и фамилия — по ним видно совпадение номеров |
| `startedAt`, `finishedAt` | ISO-время; пустой `finishedAt` = не дошёл до конца |
| `json` | весь снимок строкой |

`json` одной ячейкой намеренно: структура ответа меняется вместе с заданием, и
раскладывать её по колонкам значит переделывать лист при каждой правке.
Разбирает её сводка, а не таблица.

> Лимит ячейки Google Sheets — 50 000 знаков. Полный снимок это примерно
> 20–25 КБ, влезает с запасом.

### `loadExpert`

```
{ action: 'loadExpert', key: '7742' }
```

Ответ `{ ok: true, expert: {…} }` либо `{ ok: false }`. Нужен для возврата с
другого компьютера. Пароль здесь не спрашивается: номер и так знает только его
владелец, а без пароля эксперта страница всё равно не покажет ни описания, ни
чужой разбор.

### `loadExperts`

```
{ action: 'loadExperts', password: '<пароль команды>', corpus: 'meth-v11' }
```

Ответ `{ ok: true, experts: [ … ] }` либо `{ ok: false, error: '…' }`.
Пароль проверяется **на сервере**.

Фильтр по `corpus` — не украшение: ответы по разным версиям методологии
относятся к разным текстам, и сведённые в одну цифру они врут. Сводка это
поймает и предупредит, но лучше не привозить их вместе.

---

## 5. Сколько экспертов нужно

Восемь–двенадцать. На шести доля согласия считается, но один человек двигает её
на 17 процентных пунктов, и отличить «описание не работает» от «одному эксперту
не зашло» уже нельзя. Сводка сама предупредит, если их меньше восьми.

---

## 6. Требование к адресу: только https

Расшифровка использует `crypto.subtle`, а он работает лишь в защищённом
контексте: **https**, `localhost` и файл, открытый с диска. По обычному
**http** браузер его запрещает, и страница честно об этом скажет вместо того,
чтобы молча не открыться.
