# Экспертная валидация методологии — что нужно от бэкенда и как это запустить

Экран эксперта (`expert.html`) и сводка (`expert-report.html`) работают **без
бэкенда**: всё живёт в `localStorage`, на финише эксперт скачивает свой ответ
файлом, сводка эти файлы принимает. Бэкенд нужен, чтобы ответы не зависели от
того, не почистил ли эксперт браузер, и чтобы не собирать файлы по почте.

---

## 1. Собрать корпус — это первый шаг, без него страница не откроется

```
node tools/build-expert-corpus.js ~/Desktop/FP/01_methodology_v11.md
```

Скрипт кладёт `js/expert-corpus.js` — 50 карточек, карту модели и версию
корпуса (`meth-v11`, берётся из имени файла методологии).

**Файл в `.gitignore` намеренно.** Это рубрика скоринга целиком; репозиторий
публичный, а участник, прочитавший её до кейса, ломает замер. Значит при
публикации `js/expert-corpus.js` кладётся на хостинг **отдельно от git** —
тем же способом, каким выкладывается сайт, но не через коммит.

Если файла нет, `expert.html` честно скажет об этом и не станет рисовать
пустое задание.

Скрипт при каждой сборке печатает, что вычистил и что стоит вычитать глазами.
Три предупреждения означают работу в самой методологии, а не в коде:

- **уровни без блока «Суть»** — карточка собрана из одних признаков;
- **порядок читается по одной длине карточки** — там блок Б ничего не
  измерит, описания уровней надо выровнять по объёму;
- **карточка начинается со ссылки на то, чего в ней нет** — вычистка вырезала
  предложение, на которое опиралось следующее; фразу надо переписать руками.

## 2. Два действия Apps Script

Оба добавляются в тот же веб-приложение-скрипт, что обслуживает участника, —
адрес берётся из `js/api.js` и второй раз не заводится.

### `saveExpert`

Приходит на каждое изменение, с задержкой в полторы секунды.

```
{ action: 'saveExpert', key: '<expertId>', expert: { … весь снимок … } }
```

Ответ: `{ ok: true }`. Любой другой ответ клиент считает сбоем и кладёт снимок
в очередь повторной отправки — она уже есть в `js/api.js` и работает сама.

Запись — **upsert по `key`**, одна строка на эксперта. Не append: снимок
приходит целиком и каждый раз новый, и при append лист вырастет до тысяч строк
на одного человека.

Лист `experts`, минимально достаточные колонки:

| колонка | что |
|---|---|
| `key` | id эксперта, он же ключ upsert |
| `corpus` | версия корпуса (`meth-v11`) |
| `name` | имя и фамилия |
| `startedAt`, `finishedAt` | ISO-время; пустой `finishedAt` = не дошёл до конца |
| `json` | весь снимок строкой |

`json` одной ячейкой — намеренно: структура ответа меняется вместе с заданием,
и раскладывать её по колонкам значит переделывать лист при каждой правке.
Разбирает её сводка, а не таблица.

> ⚠ Лимит ячейки Google Sheets — 50 000 знаков. Полный снимок эксперта это
> примерно 20–25 КБ, то есть влезает с запасом, но если задание вырастет,
> проверить придётся.

### `loadExperts`

```
{ action: 'loadExperts', password: '<пароль кабинета>', corpus: 'meth-v11' }
```

Ответ: `{ ok: true, experts: [ … массив снимков … ] }` либо
`{ ok: false, error: '…' }`.

Пароль проверяется **на сервере**, тем же, которым открывается кабинет. На
клиенте его проверять бессмысленно: статика отдаётся целиком любому, кто знает
адрес, — поэтому в `expert-report.html` никакого гейта нет, а есть поле, чьё
значение уходит на бэкенд.

Фильтр по `corpus` — не украшение. Ответы по разным версиям методологии
относятся к разным текстам, и сведённые в одну цифру они врут. Сводка это
поймает и предупредит, но лучше не привозить их вместе.

## 3. Как выдавать доступ экспертам

Ссылка вида `expert.html` — при первом открытии страница сама выдаёт номер и
дописывает его в адрес (`expert.html?e=ABC123-4F2`). Дальше эксперт возвращается
по этому адресу с любого устройства.

Номер показан на финише — если эксперт пересаживается за другой компьютер,
достаточно продиктовать его.

Отдельного кода на вход нет намеренно: `noindex` плюс неанонсированный адрес
здесь дают ровно ту же защиту, что клиентский пароль, и не мешают эксперту.
Если понадобится настоящее ограничение — оно делается на бэкенде, выдачей
`saveExpert` только для заранее заведённых `key`.

## 4. Сколько экспертов нужно

Восемь–двенадцать. На шести доля согласия считается, но один человек двигает
её на 17 процентных пунктов, и отличить «описание не работает» от «одному
эксперту не зашло» уже нельзя. Сводка сама предупредит, если их меньше восьми.
